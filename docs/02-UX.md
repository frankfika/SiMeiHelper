## 1. 体验原则（落到每一页）

1. **一页一事**：每页只有一个主按钮（`btn-primary`），其余都是次按钮或文字按钮。
2. **先给答案再给数据**：今天页第一屏是小美的一句话 + 三件事，图表都在下面或二级页。
3. **全部可选，自动保存**：打卡没有必填项；每点一下就保存，不存在"没保存就丢了"。
4. **说人话**：用"份、杯、分钟"，不用"g/kg、kcal"；不用感叹号轰炸；不说"你应该"。
5. **医生是终点**：凡涉及剂量、停药、诊断，界面最终出口都是「生成就诊摘要」或「去医院」。
6. **难受时少打扰**：身体不舒服时界面自动"变安静"（§6.2）。

## 2. 信息架构

```
司美助手
├── [Tab 1] 今天  pages/today          ← 默认首页，AI 简报
│     ├── → 记录注射      pages/dose
│     ├── → 体重趋势      pages/trend
│     ├── → 知识卡        pages/article?id=
│     ├── → 身体很不舒服  pages/sos          （难受模式下出现）
│     └── → 问小美（带问题切到 Tab 3）
├── [Tab 2] 记录  pages/log            ← 今日打卡 + 打卡日历
│     └── → 体重趋势      pages/trend
├── [Tab 3] 小美  pages/chat           ← AI 对话
│     └── 消息内动作按钮 → dose / report / article / sos / 拨号
├── [Tab 4] 我的  pages/me
│     ├── → 用药方案      pages/plan
│     ├── → 就诊摘要      pages/report
│     ├── → 体重趋势      pages/trend
│     ├── → 设置          pages/settings
│     └── → 免责声明      pages/article?id=disclaimer
│
├── [全局] 首次启动 / 免责版本变化 → pages/onboarding（reLaunch，无 tab）
└── [全局浮层/机制]
      ├── 「问小美」入口：任何卡片上的「问小美」→ app.globalData.pendingAsk = 问题 → wx.switchTab('/pages/chat/chat')
      ├── 急症卡：对话/一句话打卡命中红旗时出现的红色卡片（含「拨打 120」）
      ├── 难受模式顶部条：今天页顶部「身体很不舒服？」→ sos
      └── 轻反馈：wx.showToast（成功）/ 页面内小字（错误），不使用 wx.showModal 做普通提示
```

一级入口 4 个（≤5 ✔）。「小美」放第 3 位并在 tab 上做强调（03-VISUAL §4.10）。

页面栈规则：二级页一律 `wx.navigateTo`；从对话 action 跳 tab 页用 `wx.switchTab`；onboarding 完成用 `wx.switchTab` 到今天页。

导航栏标题：今天「司美助手」｜记录「记录」｜小美「小美」｜我的「我的」｜dose「记录注射」｜trend「体重趋势」｜plan「用药方案」｜article「{文章标题}」｜report「就诊摘要」｜sos「身体很不舒服」｜settings「设置」｜onboarding 使用 `navigationStyle: custom`，自绘顶部（只有进度点和返回）。

## 3. 页面规格（全部 P0 页面）

### 3.1 今天 `pages/today`

**页面目标**：打开 3 秒内知道"今天我该做的三件事"和"身体现在处于什么状态"。

**内容块（从上到下）**：

**① 问候行**（无卡片背景）
- 左：「{早上好|中午好|下午好|晚上好}，{name}」（5–11 点早上、11–13 中午、13–18 下午、其余晚上；无昵称用「你好」）
- 下一行小字：「{10月5日 周日}」
- 右：阶段 pill「{递增期 · 第 5 周}」（explore 显示「观望期」，maintain 显示「维持期 · 第 {n} 周」）。点击 pill → toast 一句阶段说明（05-DATA §5.1 的"用户此时最大的问题"改写为陈述，例「递增期：身体在适应更高剂量，重点是蛋白和力量」）。

**② AI 今日简报卡**（`card-ai`，页面最显眼的卡）
- 顶部标签行：「✨ 小美今日简报」+ 右侧来源小字「{AI 生成 | 规则建议}」
- headline：1–2 行大字，例「打针后第 2 天，胃口小是正常的，先把蛋白吃够。」
- 3 行任务（每行：左侧圆形勾选指示 + 文字 + 右侧进度小字）
  - 「吃够 4 份蛋白（约 80g）」 右侧「{已记 2}/4」
  - 「喝够 11 杯水」 右侧「{6}/11」
  - 「走 30 分钟」 右侧「{20}/30 分」
  - 达标时：圆变实心 ✓，文字加删除线并降为 `text-3` 色。
  - 任务行点击：protein/water/move/strength → `switchTab` 到记录页并滚动到对应行（`globalData.focusField = 'protein'`）；dose → dose 页；weigh → 记录页体重行；rest → 无动作。
- note（可空）：小字一行。
- 卡底文字按钮：「问问小美 ›」→ pendingAsk =「关于今天的安排，我想问问」。
- 加载：规则版同步出现；LLM 生成中在来源处显示「小美在想…」（3 个跳动点），成功后内容淡入替换（200ms），失败保持原样不提示。

**③ 药物状态卡**（`card`，按状态 4 种形态）
- **active 形态**：
  - 左：`ring`（直径 160rpx）中间大字「{48}%」，下方小字「体感浓度」
  - 右上：「{替尔泊肽 5mg}」
  - 右中：时相标签 + hint，例「高峰期｜恶心、饱胀最常出现在这几天，少量多餐、蛋白优先」
  - 右下：「下次打针：{周日}（还有 {3} 天）」；当天显示「今天是打针日」（强调色）；overdue 显示「已过计划日 {1} 天」（warning 色）
  - 底部按钮：打针日/overdue 时为 `btn-primary`「记录这一针」；其他日为文字按钮「记录注射 ›」
  - 最底小字：「曲线按说明书参数估算，只是示意，不是血药检测结果。」
  - 无注射记录：环显示「--」，文案「记录第一针后，这里会显示药物在你身体里的变化」，按钮 `btn-primary`「记录第一针」。
- **explore 形态**（开始前清单卡）：标题「开始之前」；3 条可勾选清单（本地状态存于 `smh_kb_read` 的 `kb_fit/kb_prepare/kb_special` 已读即视为勾选）：「了解这药适不适合我 ›」「看看开始前要准备什么 ›」「特殊情况须知 ›」，点击进对应 article；底部文字按钮「已经开始用药了？更新用药方案 ›」→ plan。
- **maintain 形态**（体重守护区间卡）：标题「体重守护区间」；一条横向区间条（区间 = stopWeightKg ±2%，当前体重用圆点标出）；文案在区间内「在区间内，稳稳的 👍」，高于上限「比区间高了 {x}kg，留意一下」，超过 3% 时由洞察卡接手；按钮文字「记录今天体重 ›」→ 记录页。
- **prescribed（已开药未开始）**：同 explore，但清单第一项替换为「第一针怎么打 ›」，按钮 `btn-primary`「我打了第一针」→ dose（保存后 plan.status 自动改为 active，startDate = 该针日期）。

**④ 洞察卡区**（0–2 张 `insight-card`）
- 区块无标题；无卡时整块不渲染。
- 卡片：左侧 4rpx 色条（按 priority：≥80 warning 色，其他 primary 色）；标题；正文；底部按钮行：左 `btn-text`「知道了」（→ dismiss，卡片高度收起动画 200ms）；右 `btn-secondary-sm`「问小美」（→ pendingAsk = askPrompt）；若有 cta，再加一个 `btn-text`「{cta.label} ›」。

**⑤ 体重小卡**（`card`，整卡可点 → trend）
- 左：「体重」小标签；大字「{88.4} kg」；下方「比起始 {-3.6}kg（{-3.9}%）」
- 右：近 14 天迷你折线（`line-chart` mini 模式，无坐标轴，高 80rpx）
- 本周还没称：右上角小字「本周还没称哦」
- 空态（只有起始体重）：「记录几次体重后，这里会出现你的趋势」

**⑥ 阶段指南卡**（`card`，整卡可点 → article）
- 小标签「{递增期}最该知道的」
- 标题「{司美脸怎么防}」+「{2} 分钟读完 ›」
- 已读文章显示「再看一遍」

**⑦ 页脚**：小字居中「小美是 AI 陪伴助手，不能代替医生。」

**关键交互**：
- `onShow`：重算 ctx → 渲染规则版简报（若缓存命中且 hash 相同则用缓存）→ `insight.refresh()` → 异步 LLM 简报。
- 下拉刷新（`enablePullDownRefresh: true`）：强制重算简报（LLM 当天上限 3 次，超过只刷规则版）。
- 每天首次打开（`meta.lastOpenDate !== today`）且是打针日：药物卡轻微高亮（边框 primary 色 1.5s 后褪去）。

### 3.2 记录 `pages/log`（每日打卡）

**页面目标**：30 秒记完今天。

**内容块**：

**① 日期切换行**：「‹ 今天 10月5日 ›」。左右箭头切换日期（不晚于今天；早于 30 天只读并显示「超过 30 天的记录只能查看」）。

**② 一句话输入卡**（`card-ai`）
- 标题「✨ 一句话告诉小美」
- 多行输入框（`textarea`，auto-height，最少 2 行），placeholder「比如：今天 88 公斤，有点恶心，吃了 3 份蛋白，走了半小时」
- 右下按钮 `btn-secondary-sm`「帮我填」（输入为空时禁用）
- 提交后：按钮变「小美在看…」；返回结果后输入框下方出现**预览块**：
  - 标题「小美帮你理出了这些，对吗？」
  - 识别出的字段以 chip 形式列出（例「体重 88kg」「恶心·轻」「蛋白 3 份」「有氧 30 分钟」），每个 chip 右侧 ×，可单独移除
  - 按钮：`btn-primary`「填进去」→ upsertCheckin(合并)，预览消失，下方各行同步高亮 1s；文字按钮「不对，我自己填」→ 关闭预览
  - 什么都没识别到：「这句话我没读出具体数字，下面点一点也很快 👇」
  - 命中红旗：预览上方显示急症卡（§5.3 样式）
- 可识别即填写 `nlText`。

**③ 结构化打卡卡**（`card`，行之间 1rpx 分隔线；每行左标题右控件）

| 行 | 标题 | 控件 | 说明/文案 |
|---|---|---|---|
| 1 | 体重 | 数字输入（`type="digit"`，1 位小数）+ 单位「kg」 | placeholder「{上次体重}」；失焦保存；超出 30–300 显示红字「看看是不是输错了」不保存；只在当天显示"昨天 88.6"灰字参照 |
| 2 | 今天感觉 | `chip-group` 单选：「😊 不错」「😐 一般」「😣 难受」 | 对应 good/ok/bad；再次点击已选项取消 |
| 3 | 不舒服的地方 | `chip-group` 三态多选：恶心、呕吐、腹泻、便秘、反酸、胀气、乏力、头晕、注射处、掉头发 | 点一次=轻（浅色填充）、两次=重（实色填充 + 「重」角标）、三次=取消。行下方小字「点一次是轻，再点一次是重」（只在首次使用时显示，之后隐藏：`smh_meta` 不新增字段，用 `wx.getStorageSync('smh_tip_sym')` 一次性标记） |
| 4 | 蛋白 | `cup-grid`：目标数 N 个格子（形状为掌心图标「🥩」位置用圆角方块），点第 k 格=记 k 份；再点最后一格=减 0.5；格子后显示「{3}/{4} 份」 | 标题右侧「?」图标 → 底部弹出 1 份对照（05-DATA §5.2 列表） |
| 5 | 喝水 | `cup-grid`：目标数个杯子格；超出目标后末尾出现「+」格可继续加 | 「{6}/{11} 杯 · 1 杯=250ml」 |
| 6 | 有氧运动 | `chip-group` 单选：0、15、30、45、60、90 分钟 | 以分钟为单位，可再点取消 |
| 7 | 力量训练 | 开关（`switch`） | 文案「做了力量训练（深蹲、哑铃、弹力带都算）」 |
| 8 | 食欲 | `chip-group` 单选：「小」「正常」「大」 | low/normal/high |

- 第 3 行若出现任何"重"或选了呕吐、或第 2 行选「难受」，卡片顶部插入一行提示条（warning 浅底）：「今天辛苦了。要不要看看怎么缓解？」+ 文字按钮「看看 ›」（→ sos）。

**④ 完成按钮**（固定在 tab bar 上方，`btn-primary` 全宽）
- 未完成：「完成打卡」；已完成：「已完成 ✓ 更新一下」（次按钮样式，仍可点，点后刷新 completedAt）。
- 点击后：`completeCheckin` → `ai.checkinFeedback` → 在按钮上方出现反馈气泡（`bubble-ai` 样式，3s 后保留为卡片顶部一行小字，不自动消失）→ `insight.refresh()`。
- `wx.vibrateShort({type:'light'})`。

**⑤ 打卡日历**（`card`）
- 标题「这个月」+ 右侧「体重趋势 ›」→ trend
- 7 列月历：已完成日=primary 实心小圆点；有记录未完成=空心圆；难受日=圆点下方小三角（warning 色）；打针日=日期下方「💉」（10px 级小字）。
- 点日期 → 页面顶部日期切换到该日（复用同一页面）。
- 顶部统计：「连续 {7} 天 · 本月 {18} 天」。

**空态**：首次进入（无任何打卡）时，一句话输入卡上方显示一行引导「第一次打卡？试试跟小美说一句话 👇」。

**关键交互**：
- 所有控件 `bindchange/bindtap` → 立刻 `upsertCheckin`；无保存按钮。
- 从今天页任务行进入时，`globalData.focusField` 存在 → `wx.pageScrollTo({ selector: '#row-protein' })` 并高亮该行 1s，然后清空。
- 30 秒路径（熟练用户）：点「😐 一般」→ 点蛋白第 3 格 → 点水第 6 格 → 点「30」分钟 → 「完成打卡」= 5 次点击。

### 3.3 小美 `pages/chat`

**页面目标**：任何关于用药、吃、动、反应的问题，在这里得到有温度、安全的回答。

**内容块**：

**① 安全常驻条**（吸顶，高 64rpx，浅灰底）：「小美是 AI 陪伴助手，不是医生。不提供诊断和剂量建议。」规则模式下右侧追加「· 离线模式」小字。

**② 消息列表**（`scroll-view scroll-y`，`scroll-into-view` 定位到最后一条）
- 用户气泡：右对齐，primary 色底白字。
- 小美气泡：左对齐，头像「✨」圆形小标（48rpx），白底卡片（暗色模式为 surface）。
- 小美消息下方 actions：横向排列 `btn-secondary-sm`；`kind` 处理：
  - `navigate` → `wx.navigateTo(payload)`；`switchTab` → `wx.switchTab`
  - `apply_checkin` → `storage.upsertCheckin(today, payload)` → toast「已记到今天 ✓」→ 按钮变「已记录」禁用
  - `call` → `wx.makePhoneCall({ phoneNumber: payload })`
  - `ask` → 作为用户消息直接发送 payload
- 急症消息（`type:'safety'`）：使用急症卡样式（danger 浅底 + 左色条 + 「⚠️」），「拨打 120」为 danger 实色按钮。
- 来源标记：`source:'rules'` 且 `offline` 时，气泡下方小字「离线回答」；`source:'guard'` 时小字「已按安全规则改写」。
- 长按小美气泡 → `wx.setClipboardData` 复制。
- 日期分隔：跨天时插入居中小字「10月4日」。

**③ 空态（无历史消息）**
- 居中：大号「✨」+「我是小美」+ 副文案「用药、吃饭、运动、身体反应，都可以问我。\n我会记得你的情况，回答更贴近你。」
- 下方 4 个推荐问题（`rules.suggestedQuestions`），竖排 `chip` 大号样式，点击即发送。

**④ 输入区**（固定底部，位于自定义 tab bar 之上）
- 上方：横向滚动快捷 chip（与空态同一组 4 个问题，有历史消息时也显示，键盘弹起时隐藏）。
- 输入框（`textarea` auto-height，最多 4 行，maxlength 300）placeholder「问小美任何问题…」+ 发送按钮（圆形 primary，输入为空禁用）。
- `adjust-position` 设为 false，监听 `bindkeyboardheightchange` 手动抬高输入区。
- 发送中：插入"小美正在输入"气泡（三个跳动点）；发送按钮禁用；15s 超时后用规则回复替换。

**关键交互**：
- `onShow`：若 `globalData.pendingAsk` 有值 → 立刻作为用户消息发送并清空。
- 用户消息与小美回复都 `storage.appendChat`。
- 历史 >200 条自动截断（无提示）。
- 右上角无菜单；清空对话在设置页。

### 3.4 我的 `pages/me`

**页面目标**：查看/修改我的档案与方案，拿到就诊摘要。

**内容块**：
1. **档案头**（无卡片）：头像位放大号 emoji「🌱」（不取微信头像）；「{昵称或"给自己起个名字"}」（点击 → 弹出 `wx.showModal({editable:true})` 修改昵称，≤10 字）；下方小字「{165cm · 起始 92kg · 目标 80kg}」→ 点击进入编辑（使用同一 modal 序列：身高/目标体重，**不**允许修改起始体重）。
2. **三格统计**（一张卡内三等分）：「已用药 {5} 周」「累计 {-3.6}kg」「连续打卡 {7} 天」。观望期第一格显示「观望中」。
3. **列表卡 1**：
   - 「💉 用药方案」右侧灰字「{替尔泊肽 5mg · 每周日}」→ plan
   - 「📋 就诊摘要」右侧灰字「复诊时给医生看」→ report
   - 「📈 体重趋势」→ trend
   - 「🎯 我的每日目标」右侧灰字「蛋白 4 份 · 水 11 杯」→ 点击弹出 `wx.showModal` 展示 targets.basis（只读）
4. **列表卡 2**：
   - 「⚙️ 设置」→ settings
   - 「📄 免责声明」→ article?id=disclaimer
   - 「ℹ️ 关于司美助手」右侧版本号「v1.0.0」→ toast
5. 页脚：「你的数据只保存在这部手机里。」

### 3.5 记录注射 `pages/dose`

**页面目标**：10 秒记一针，并自动轮换部位。

## 4. 核心流程

### 4.1 首次启动 Onboarding（6 步，单页面内切换）

页面结构：顶部自绘栏（左「‹」返回上一步，第 1 步隐藏；中间 6 个进度点）；中部内容；底部固定主按钮。步骤切换水平滑动动画 250ms。每步完成写 `meta.onboardingStep`。

**Step 1 欢迎**
- 大号「🌱」
- 标题「你好，我是司美助手」
- 正文「用司美格鲁肽、替尔泊肽减重的路上，\n吃什么、怎么动、身体反应正不正常、什么时候该找医生——\n我和 AI 小美陪你一起。」

- 主按钮「开始」

**Step 2 免责声明**

- 勾选框「我已阅读并理解以上内容」
- 主按钮「我明白了，继续」（未勾选禁用）→ 写 disclaimerAcceptedVersion/At

**Step 3 身体数据**
- 标题「先认识一下你」 副标题「只保存在你的手机里」
- 字段：昵称（选填，placeholder「怎么称呼你」）、性别（chip：女/男/不愿透露）、出生年份（`picker mode=selector`，范围 1930–今年-18，默认 1990）、身高（`digit`，cm）、现在体重（`digit`，kg）、目标体重（选填）

### 4.2 每日打卡闭环（目标 ≤ 30 秒）

```
今天页 简报任务行「吃够 4 份蛋白」 ──tap──> 记录页（滚动到蛋白行）
   │                                          │
   │                         点 感觉 → 蛋白格 → 水格 → 运动 chip（每点即存）
   │                                          │
   │                                     「完成打卡」
   │                                          │
   │                       反馈气泡（≤40 字） + insight.refresh()
   │                                          │
   └──── 切回今天页 onShow ──> hash 变化 → 简报重算（任务打勾）、洞察卡更新
```

另一路径（AI native）：记录页一句话 →「帮我填」→ 预览 →「填进去」→「完成打卡」= 输入 + 3 次点击。

第三路径：小美对话中说「今天有点恶心」→ 小美回复下方 action「记到今天打卡」→ 一键写入。

### 4.3 AI 对话交互规范

**AI native 的五个落点**（工程必须全部实现）：

| # | 位置 | 体现 | 触发 | 实现 |
|---|---|---|---|---|
| 1 | 今天页简报卡 | AI 为"今天的你"写一句话 + 三件事 | onShow（hash 变化）、下拉刷新 | 规则版同步 → LLM 异步替换（05-DATA §6.6） |
| 2 | 今天页洞察卡 | 系统主动发现问题并开口 | onShow、完成打卡、记录注射 | `insight.refresh()`（05-DATA §7） |
| 3 | 记录页一句话 | 说一句话就能打卡 | 用户提交 | `ai.parseCheckin` |
| 4 | 全局「问小美」 | 每张卡都能带着上下文提问 | 点按钮 | `globalData.pendingAsk` |
| 5 | 对话 actions | 小美能"帮你做事"（记打卡、去记针、出摘要、拨号） | 回复附带 | 05-DATA §6.3 actions 列 |

**对话规范**：
- 每轮回复 ≤ 200 字（LLM），规则模板 ≤ 250 字；段落间空一行；条目用「·」或数字。
- 语气：第二人称"你"，不用"您"；可用少量 emoji（每条 ≤ 2 个）；不用"亲"。
- 小美永不说的话：「你应该加量」「可以停药了」「你得了…」「这个药没用」「你太胖了」。
- 当用户情绪低落（「好难」「想放弃」「没用」）：先共情一句再给建议（LLM 系统提示已涵盖；规则模式走兜底时，兜底文案前加「辛苦了，愿意跟我说说是哪里最难吗？」——条件：文本含 `难|放弃|崩溃|焦虑|烦`）。
- 上下文：每次请求都带最新 `contextToText`；历史只带最近 10 条 text 消息。
- 失败策略：LLM 失败 → 规则回复 + 「离线回答」标；连续 3 次失败 → 本次会话内直接用规则，不再尝试（内存标记）。

**洞察卡如何触发（用户视角）**：用户完成打卡 → 回到今天页 → 若新卡出现，卡片从上方淡入（opacity 0→1，translateY 16rpx→0，250ms）。同一时间最多 2 张；关闭后冷却期内不再出现。

## 5. 通知与提醒策略

### 5.1 原则
- **MVP 无服务器推送**。提醒依赖：① 手机系统日历（`wx.addPhoneRepeatCalendar` / `wx.addPhoneCalendar`）；② 打开小程序时的页面内提示。
- 每次打开最多一个"主动打扰"（药物卡高亮 或 洞察卡淡入，二者可同时存在，但不弹 modal）。
- 不发"你已经 3 天没打卡了"这类内疚式提醒。断签后回来，打卡页顶部显示「欢迎回来 🌱」（距上次打卡 ≥ 3 天时，仅当天显示）。

### 5.2 提醒清单

| 提醒 | 渠道 | 内容 | 触发/设置 |
|---|---|---|---|
| 每周打针 | 系统日历重复事件 | 标题「💉 今天是打针日」描述「打完记得在司美助手里记一下」；每周 `injectWeekday` 9:00，提前 0 分钟提醒 | onboarding Step 6 / dose 首次保存后 / plan 页 |
| 复诊 | 系统日历单次事件 | 「🏥 复诊日：带上就诊摘要」当天 8:00，提前 1 天提醒（`alarmOffset: 86400`） | plan 页填写复诊日后 |
| 每日打卡 | 系统日历重复事件（可选） | 「🌱 花 30 秒和小美打个卡」每天 21:00 | plan/settings 页手动开启 |
| 打针日（应用内） | 今天页药物卡 | 「今天是打针日」+ 主按钮 | phase / weekday |
| 漏针 | 洞察卡 `dose_overdue` | 05-DATA §7.2 | 自动 |
| 复诊临近 | 洞察卡 `visit_soon` | | 自动 |

### 5.3 日历 API 调用规格

```js
wx.addPhoneRepeatCalendar({
  title: '💉 今天是打针日',
  startTime: <下一个 injectWeekday 的 09:00，秒级时间戳>,
  description: '打完记得在司美助手里记一下',
  repeatInterval: 'week',
  alarm: true, alarmOffset: 0,
  success: () => 写 med.calendarAdded.inject = true; toast('已加到手机日历'),
  fail: () => toast('没加上也没关系，打开小程序时我会提醒你')
})
```
（`startTime` 单位为秒。复诊用 `wx.addPhoneCalendar`，`allDay:false`。）

### 5.4 加日历引导时机
仅在以下时刻引导一次（`settings.reminders.askedCalendar = true` 后不再主动引导，plan 页按钮常驻）：onboarding Step 6（次按钮，不强制）；或第一次在 dose 页保存后（`wx.showModal`：「要把每周打针日加到手机日历吗？」按钮「加一下」/「先不用」）。

### 5.5 P1：订阅消息
接入云开发后，在 dose 保存成功时调用 `wx.requestSubscribeMessage`（一次性订阅，每次记录后续订下一针），云函数定时发送。MVP 不实现。

## 6. 无障碍与边界情况

### 6.1 无障碍
- 最小正文字号 28rpx，辅助文字不小于 24rpx；所有可点区域 ≥ 88×88rpx（chip 高度 72rpx + 外边距补足热区）。
- 颜色不作为唯一信息载体：达标=✓+删除线；重度症状=实色+「重」角标；速度分档=颜色+文字。
- 文本对比度：正文 ≥ 4.5:1（03-VISUAL 色板已校验）。
- 关键图形元素加 `aria-label`：ring「体感浓度 48%」；cup-grid 每格「第 3 杯，已喝」；chip 选中状态 `aria-selected`。
- 支持系统字体放大：布局不写死高度（除 tab bar 与输入区），文本允许换行。
- 动画：所有动效 ≤ 300ms；不做循环动画（"小美在想"跳动点除外，最长 15s）。

### 6.2 难受模式（副作用重灾期的界面降级）

触发：`plan.isBadDay(todayCheckin) === true`。

| 区域 | 正常 | 难受模式 |
|---|---|---|
| 今天页顶部 | 问候行 | 问候行上方插入 warning 浅底条：「身体很不舒服？」+「看看 ›」→ sos |
| 简报 | 正常模板 | 05-DATA §6.6 优先级 1 模板（休息/补水/红旗） |
| 药物卡 | 完整 | 保留（打针日信息仍重要），hint 改为「这几天难受的话，打针前可以先问问医生」（仅在打针日前 1 天内） |
| 洞察卡 | 正常 | 只显示 priority ≥ 70 的 |
| 体重小卡 | 显示 | **隐藏** |
| 阶段指南 | 阶段推荐 | 固定推荐 kb_nausea（有呕吐时 kb_red_flags） |
| 记录页 | 全部行 | 蛋白/水/运动行收进「其他（今天可以不填）」折叠区，默认折叠 |
| 小美空态问题 | 阶段问题 | 05-DATA §6.10 badDay 组 |
| 文案 | — | 不出现任何"目标""达标""加油" |

退出：次日自动；或今天页顶部条右侧「我好多了」→ `upsertCheckin(today, { feel:'ok', symptoms: 将所有 2 降为 1，删除 vomiting })` → 立即恢复正常模式。

### 6.3 停药/维持模式
- 今天页药物卡 → 体重守护区间卡；简报走 maintain 模板；打针日相关提醒全部隐藏；dose 页从入口中隐藏（今天页无记录注射按钮；plan 页仍可改回"正在用"）。
- 打卡页不变（体重行上移到第一行并标注「维持期每周至少称一次」）。

### 6.4 其他边界

| 情况 | 处理 |
|---|---|
| 换药（司美→替尔泊肽） | feltPct 只计算当前药；药物卡副文案加一行「刚换药，前几周数值偏低是正常的」（换药后 28 天内） |
| 记录了未来时间的注射 | picker end 限制，不可能发生 |
| 同一天记了两针 | 允许，但触发 §3.5 间隔警告 |
| 体重骤变（与上次差 > 5kg 且间隔 < 7 天） | 保存后行下方灰字「和上次差得有点多，看看是不是输错了」，不阻止 |
| 跨午夜打卡 | 以手机本地日期为准；0–4 点打开时记录页默认日期仍为今天，但日期行右侧显示「记昨天？」文字按钮 |
| 存储写满 | storage.set 自动截断对话；仍失败 toast「存储空间不足」 |
| 设置了 LLM 但断网 | 15s 超时 → 规则回复；简报静默保持规则版 |
| 首次进入 tab 页前未完成 onboarding | `ensureOnboarded` reLaunch |
| 系统暗色模式 | 全部页面跟随，canvas 监听 `wx.onThemeChange` 重绘 |
| 用户删除了最后一针 | 药物卡回到"无注射记录"形态 |
| 18 岁以下 | onboarding 阻断（§4.1 Step 3） |
